## 1. Executive Summary & Problem Diagnosis

During the Milestone 1 Gate evaluation, challengers `m1_challenger_1` and `m1_challenger_2` uncovered critical gaps in the Python analysis service's epistemic confidence classification and engine runner pipeline. These gaps violate the non-negotiable architectural invariant defined in `PROJECT.md` line 30:

> *"Every finding MUST be backed by an immutable Evidence record with a cryptographic SHA-256 hash and classified into one of 4 strict confidence classes: VERIFIED (1.0), RULE_DERIVED (0.85), INFERRED (0.60), UNKNOWN (0.30). LLM outputs can NEVER exceed INFERRED (0.60)."*

### Root Causes Identified

1. **Missing Evidence Demotion Incomplete in `confidence.py:25`**:
   ```python
   # Current code:
   if missing_evidence or (not finding.evidence and finding.confidence == ConfidenceClass.VERIFIED):
       finding.confidence = ConfidenceClass.UNKNOWN
       finding.confidence_score = 0.30
   ```
   - **Flaw**: The condition `finding.confidence == ConfidenceClass.VERIFIED` restricts automatic empty-evidence demotion strictly to findings that were previously `VERIFIED`.
   - **Impact**: Any finding initialized with `RULE_DERIVED` or `INFERRED` that has `evidence = []` is **never demoted** when `missing_evidence` defaults to `False`. Such findings escape to callers claiming `0.85` or `0.60` confidence without any backing artifact evidence.

2. **Rule Evaluation Inversion in `confidence.py:19-27`**:
   ```python
   # Current code:
   # Rule 1: Non-negotiable LLM Boundary
   if is_ai_generated:
       if finding.confidence in (ConfidenceClass.VERIFIED, ConfidenceClass.RULE_DERIVED):
           finding.confidence = ConfidenceClass.INFERRED
       finding.confidence_score = min(finding.confidence_score, 0.60)

   # Rule 2: Missing mandatory evidence demotes to UNKNOWN
   if missing_evidence or (not finding.evidence and finding.confidence == ConfidenceClass.VERIFIED):
       finding.confidence = ConfidenceClass.UNKNOWN
       finding.confidence_score = 0.30
   ```
   - **Flaw**: When an AI-generated finding lacks evidence (`evidence = []`, `is_ai_generated = True`), Rule 1 runs first and mutates `finding.confidence` to `INFERRED`. When Rule 2 runs immediately after, `finding.confidence == ConfidenceClass.VERIFIED` evaluates to `False`.
   - **Impact**: The AI hallucination without evidence retains `INFERRED (0.60)` instead of being demoted to `UNKNOWN (0.30)`. Missing evidence must always take precedence over AI bounding.

3. **`EngineRunner.execute` Provenance Blind Spot in `runner.py:27`**:
   ```python
   # Current code:
   for finding in response.findings:
       ConfidenceClassifier.classify_finding(finding)
   ```
   - **Flaw**: `EngineRunner.execute` invokes `classify_finding` with default arguments (`is_ai_generated=False`, `missing_evidence=False`). It fails to inspect:
     - Request-level configuration flags (`request.configuration.get("is_ai_generated")`)
     - Finding-level attributes (`finding.is_ai_generated` or `finding.technical_details.get("is_ai_generated")`)
     - Evidence-level provenance (`evidence.provenance == ConfidenceClass.INFERRED` or `evidence.source_type == TrustLevel.INFERRED`)
   - **Impact**: Engines returning findings generated by LLMs or probabilistic routers with `confidence = VERIFIED` bypass the demotion pipeline entirely, emitting unverified claims as `VERIFIED (1.0)`.

## 2. Epistemic Invariant Specification & Truth Table

The Confidence Classifier enforces a strict hierarchy:

$$\text{Evidence Absence} \prec \text{LLM / Inferred Source} \prec \text{Deterministic Rule} \prec \text{Exact AST/Parser Match}$$

### Comprehensive State Transition Matrix

| Initial Confidence | Initial Score | Evidence Present? | AI Generated / Inferred Provenance? | Final Confidence | Final Score | Rationale |
|---|---|---|---|---|---|---|
| `VERIFIED` | 1.00 | **No** (`[]`) | No | `UNKNOWN` | **0.30** | Missing evidence unconditional demotion |
| `RULE_DERIVED` | 0.85 | **No** (`[]`) | No | `UNKNOWN` | **0.30** | Fixes Gate Bug 1: Rule findings require proof |
| `INFERRED` | 0.60 | **No** (`[]`) | No | `UNKNOWN` | **0.30** | Unevidenced inferences cannot exceed UNKNOWN |
| `UNKNOWN` | 0.30 | **No** (`[]`) | No | `UNKNOWN` | **0.30** | Retains baseline UNKNOWN |
| `VERIFIED` | 1.00 | **No** (`[]`) | **Yes** | `UNKNOWN` | **0.30** | Fixes Gate Bug 2: Missing evidence takes precedence over AI |
| `RULE_DERIVED` | 0.85 | **No** (`[]`) | **Yes** | `UNKNOWN` | **0.30** | Missing evidence takes precedence over AI |
| `INFERRED` | 0.60 | **No** (`[]`) | **Yes** | `UNKNOWN` | **0.30** | Missing evidence takes precedence over AI |
| `VERIFIED` | 1.00 | Yes | **Yes** | `INFERRED` | **0.60** | LLM output capped at INFERRED (0.60 ceiling) |
| `RULE_DERIVED` | 0.85 | Yes | **Yes** | `INFERRED` | **0.60** | LLM output capped at INFERRED (0.60 ceiling) |
| `INFERRED` | 0.95 (tampered) | Yes | **Yes** | `INFERRED` | **0.60** | Clamped to INFERRED ceiling |
| `UNKNOWN` | 0.80 (tampered) | Yes | **Yes** | `UNKNOWN` | **0.30** | Clamped to UNKNOWN ceiling |
| `VERIFIED` | 1.00 | Yes (Inferred source) | No (flag=False) | `INFERRED` | **0.60** | Auto-detected: Evidence has INFERRED provenance |
| `VERIFIED` | 1.00 | Yes | No | `VERIFIED` | **1.00** | Valid deterministic AST/exact evidence |
| `RULE_DERIVED` | 0.85 | Yes | No | `RULE_DERIVED` | **0.85** | Valid deterministic rule evidence |

## 3. Component Fix Strategy

### 3.1 `services/analysis-python/src/platform/confidence.py`

#### Changes:
1. Import `TrustLevel` from `src.models.enums`.
2. Add `@classmethod def classify(...)` matching the interface specification, while aliasing `classify_finding = classify` to preserve 100% backward compatibility for all existing callers.
3. Invert execution order:
   - **Step 1 (Precedence)**: Missing Evidence Demotion. If `missing_evidence=True` or `not finding.evidence` or `len(finding.evidence) == 0`, immediately set `confidence = ConfidenceClass.UNKNOWN`, `confidence_score = 0.30`, and return.
   - **Step 2**: LLM / AI Boundary. If AI-generated (via parameter, finding metadata, or evidence provenance), demote `VERIFIED` and `RULE_DERIVED` to `INFERRED`, capping `confidence_score` at `0.60`.
   - **Step 3**: Score Synchronization. Clamp and synchronize `confidence_score` to canonical mapping (`CONFIDENCE_SCORE_MAP`).
4. Implement automatic multi-source AI detection:
   ```python
   effective_ai = (
       is_ai_generated
       or getattr(finding, "is_ai_generated", False)
       or bool(finding.technical_details.get("is_ai_generated"))
       or bool(finding.technical_details.get("ai_generated"))
       or any(
           e.provenance == ConfidenceClass.INFERRED or e.source_type == TrustLevel.INFERRED
           for e in (finding.evidence or [])
       )
   )
   ```

### 3.2 `services/analysis-python/src/core/runner.py`

#### Changes:
1. Import `ConfidenceClass, TrustLevel` from `src.models.enums`.
2. In `EngineRunner.execute`, inspect the execution context:
   - Check if request-level configuration specifies AI: `request.configuration.get("is_ai_generated")` or `request.options.custom_params.get("is_ai_generated")` or `getattr(engine, "is_ai_engine", False)`.
3. In the finding post-processing loop:
   - Compute `finding_is_ai` combining request context, finding fields, and evidence provenance.
   - Compute `has_no_evidence = not finding.evidence or len(finding.evidence) == 0`.
   - Call `ConfidenceClassifier.classify(finding, is_ai_generated=finding_is_ai, missing_evidence=has_no_evidence)`.

### 3.3 `services/analysis-python/src/models/finding.py`

#### Changes:
Add `is_ai_generated: bool = Field(default=False, description="Flag indicating LLM or probabilistic generation")` to the `Finding` Pydantic model. This establishes a first-class typed attribute for findings while maintaining zero breaking changes via default value.

### 3.4 `services/analysis-python/tests/unit/test_confidence.py`

#### Changes:
Replace the minimal test file with an 11-test comprehensive suite covering:
1. `test_llm_output_is_demoted_to_inferred`: AI with valid evidence demotes to `INFERRED (0.60)`.
2. `test_missing_evidence_demoted_to_unknown`: Explicit `missing_evidence=True` demotes to `UNKNOWN (0.30)`.
3. `test_rule_derived_without_evidence_demotes_to_unknown`: `RULE_DERIVED` with empty evidence demotes to `UNKNOWN (0.30)` (resolves Gate failure).
4. `test_ai_finding_without_evidence_demotes_to_unknown_not_inferred`: AI without evidence demotes to `UNKNOWN (0.30)` (resolves Gate failure).
5. `test_ai_rule_derived_without_evidence_demotes_to_unknown`: AI + `RULE_DERIVED` without evidence demotes to `UNKNOWN (0.30)`.
6. `test_evidence_provenance_inferred_triggers_ai_demotion`: Evidence having `TrustLevel.INFERRED` triggers demotion without explicit flag.
7. `test_finding_is_ai_generated_field_triggers_demotion`: `finding.is_ai_generated=True` triggers demotion.
8. `test_technical_details_ai_flag_triggers_demotion`: `finding.technical_details={"is_ai_generated": True}` triggers demotion.
9. `test_deterministic_findings_with_evidence_retain_confidence`: Valid `VERIFIED` and `RULE_DERIVED` findings retain full confidence and scores.
10. `test_score_tampering_clamped`: Elevated scores (e.g. 0.99) are clamped to canonical limits.
11. `test_classify_finding_backward_compatibility_alias`: Verifies `classify_finding` is an exact alias of `classify`.
